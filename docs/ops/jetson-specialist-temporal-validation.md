# Jetson 专用小模型与时序融合验证

日期：2026-09-12。结论：**本轮局部验证完成；这个具体组合仍未达到 Camera Edge 最低使用要求。专用手部观测与挥手事件获得有限正向证据，完整多专家路线尚未充分验证。**

没有接入 MobileVLM、其他 VLM/LLM 或 Personal Runtime。第二条“专用模型＋MobileVLM”路线未启动。后续新增训练型手势／物品分类的结果见[扩展验证](jetson-specialist-expanded-validation.md)，不追溯改变本轮测量。

## 改变了什么

此前 YOLO 姿态腕点在明显举手图中也不可用。本轮使用 Jetson 已安装的 MediaPipe 0.10.18：独立掌部检测／21 点手部模型、面部检测／468 点面部模型、身体检测／33 点姿态模型。共享同一帧 RGB，依次运行，随后按源视频时间融合。

没有安装包、改动 NVIDIA PyTorch、清理旧环境或停止其他服务。实验目录是 `/home/jetson/openhalo-specialist-temporal/`。模型配置与六个模型文件的 SHA-256 在 JSON 证据中。

手部模型的 handedness probability 是左右手分类概率，不是检出置信度。Hands/FaceMesh 不提供逐关键点置信度；身体 visibility 单独保留。实现依据：[MediaPipe Hands](https://chuoling.github.io/mediapipe/solutions/hands.html)、[Face Mesh](https://chuoling.github.io/mediapipe/solutions/face_mesh.html)。

## 实验与结果

| 实验 | 结果 | 能证明什么 |
| --- | --- | --- |
| 单张旧举手图 smoke test | 检出 1 只手、1 张脸 | 专用手部输入可用，不能证明连续动作理解 |
| v1：两段旧挥手视频，各 80 个采样帧 | 两段都未报挥手；分别 25、22 帧检出手 | 初版要求手掌高于下巴，而实际在胸前挥动，规则错误 |
| v2：对同一批原始观测重新融合 | greeting-a 检出挥手但分裂成两段；greeting-b 漏检 | 修正高度前提有效，但观测丢失／多手歧义仍破坏连续性；这是开发集修正规则，不是独立验收 |
| v2：用户配合的新录制约 60 秒视频 | 3 次挥手均各触发 1 次；其他时段未报挥手 | 同一人、同一场景的新片段正向证据；不是总体召回率／误报率 |
| 旧吃东西视频／低头视频 | 未报挥手；没有识别出吃东西或屏幕注意 | 没有波及这些负例，但复杂日常状态仍不具备 |
| 重复同一举手图约 4 秒 | 手部姿态保持，0 次挥手 | 合成静态控制通过；不等于真实静止手抖动控制 |

v2 不再把“手掌在脸下方”当作放下：输出 `open_hand_visible`、`hand_visible`、`unknown`。单人单只候选手时，以面宽归一化的掌部水平往复作为挥手证据：1.6 秒窗口、至少两次方向反转、跨度至少 0.35 面宽；姿态状态需要 0.3 秒持续证据。没有根据这段新视频再调阈值。

身体姿态仍运行并记录，但其腕点未被采用来填补 v2 的手部丢失。因此正向结果来自**手部＋面部参考＋时序规则**，尚未证明加入身体模型有增益。

## 新片段核对

用户确认准备好后，CSI 录制 3600 帧，1280×720，约 60 秒。既定动作提示是“张开手停住两秒→左右挥手→放下”。实际录像包含三次挥手。人工查看半秒间隔画面核对以下宽时间窗；没有独立逐帧标注，也没有把提示直接当作每个动作的真值。两秒静止段未单独验收。

| 实际动作宽时间窗（秒） | 首次报挥手（秒） | 后续结果 |
| --- | --- | --- |
| 3.5–7.5 | 5.845 | 7.143 手部运动观测丢失；7.576 手部状态 unknown |
| 20.0–23.5 | 22.080 | 22.729 手部运动观测丢失；23.162 手部状态 unknown |
| 34.5–37.5 | 36.799 | 37.016 手部运动观测丢失；37.449 手部状态 unknown |

这三个窗共 48 个采样帧，仅 32 帧检出手；这不是逐帧手部召回率，因为窗内包含起落和无手画面。窗外 229 帧没有报挥手。后段转头导致面部丢失，48.921 秒报局部跟踪丢失，不能声称已验证多人／侧脸跟踪恢复。

新片段共 277 个采样帧：24 帧稳定 `open_hand_visible`，253 帧 `unknown`。多数 unknown 对应手未进入画面或面部丢失；它不能回答整个人“当前在做什么”。手检出 32 帧、单脸检出 224 帧、身体模型返回 277 帧；最后一项不代表姿态分类正确。

**没有报出可靠的“举起→挥动→放下”完整语义链。** 检出手只是观察到姿态，丢失手也不是证据充分的放下动作。没有吃东西、物体交互、看屏幕、可打扰性或身份判断。

## 耗时与资源

新片段按名义 5 Hz 抽样，实际相邻采样约 0.216 秒（按 frame-index / 文件 FPS）。所有帧按时间顺序处理，但这是**录完后回放**，不是并发采集的实时管线。

| 指标 | 实测 |
| --- | --- |
| 手部模型平均耗时 | 80.49 ms |
| 面部模型平均耗时 | 24.93 ms |
| 身体模型平均耗时 | 80.28 ms |
| 三模型合计平均耗时 | 185.70 ms |
| 选中帧处理 P95 / 最大耗时 | 262.47 / 332.33 ms |
| 整机 RAM 范围 | 3149–3805 / 7620 MB |
| 已占用 swap | 840 MB，全程读数未增加；没有证明无 swap 依赖 |
| GR3D / CPU 温度 | 采样 GPU 0%；CPU 50.9–53.2°C |

耗时统计去掉各视频第一帧，包含选中帧读取、RGB 转换、模型和融合；不含跳过帧的所有解码工作、采集／编码、排队、传输和 Runtime。三个模型运行于 CPU TFLite/XNNPACK；GPU 0% 不是 GPU 加速结果。采样500 ms 的 tegrastats 可能遗漏短峰值。

**不能以 262 ms 宣布五秒事件标签 P95 达标。** 源视频内事件触发需要累积多帧，且没有测量采集到最终消费端的延迟。本轮没有进行长期运行、积压／丢帧策略或资源优化实验。

## 验收分项

| 分项 | 本轮状态 |
| --- | --- |
| 比原 YOLO 腕点获得更多真实手部证据 | 完成有限验证 |
| 新片段三次挥手及窗外误报检查 | 完成有限验证 |
| 旧片段持续动作覆盖 | 未通过：第二段漏检，第一段分裂 |
| 真实静止、遮挡、多人交叉、进出画面 | 未验收；合成控制／单元测试不替代实测 |
| 举起／放下、动作结束与完整顺序 | 未通过最低能力要求 |
| 吃东西、看屏幕、人—物交互 | 未实现可验收能力 |
| 实时事件标签 P95 ≤5秒、稳定性、恢复 | 未验收 |
| Runtime 接入／完整 Camera Edge | 未接入，未接受 |

7 个融合边界单元测试通过：静止不报挥手、胸前往复无需高于下巴、手丢失不叫放下、时间断档不连接运动／去抖、多人歧义、局部新轨迹重新累积证据、时间戳严格递增。这些仅验证规则的软件边界。

因此，**当前具体组合仍不能作为合格 Camera Edge 交付**。值得保留的是轻量手部动作触发组件；不应将三次挥手成功扩大为完整日常行为理解已解决。下一步若继续这条路线，应先解决连续观测和真实起落／结束证据，再评估加入其他专家是否提供实测增益。
